我的博客发布流水线：从 Obsidian 到 Cloudflare Pages

发表于2026-09-20|更新于2026-09-20|折腾吧
|总字数:702|阅读时长:2分钟|浏览量:

博客长期疏于更新，一个重要原因是”发布”这件事本身有摩擦：切环境、跑命令、传图。这篇记录我把发布链路自动化的方案——目标是让”写完”到”上线”中间尽量没有手工步骤。

目标：消灭发布时的决策

写作的产出在 Obsidian 里。我不想每次发文都去想”要不要压图、front-matter 怎么写、部署命令是啥”。所以把整条链路固定下来：Obsidian 写 Markdown → git push → GitHub Actions 自动构建 Hexo → 部署到 Cloudflare Pages。

整体架构

flowchart LR
    A[Obsidian 写 Markdown] -->|frontmatter 标 publish| B[git push]
    B --> C[GitHub Actions]
    C --> F[exiftool 去 EXIF]
    F --> D[Hexo generate]
    D --> E[Cloudflare Pages 部署上线]
    G[OSS 图床] -.图片引用.-> D
    E --> H{AI 爬虫 / 搜索引擎}
    H -.收录.-> I[Google / Bing]
    H -.引用.-> J[AI 搜索]

几个关键点：

  • 源在 Obsidian：用 frontmatter 的一个字段标记哪些笔记要发布，没标的不进流程。
  • 构建交给 CI：GitHub Actions 跑 Hexo，去掉本地 Windows 环境的依赖——以前换台机器就跑不起来，现在哪都能发。
  • 部署到 Cloudflare Pages：静态托管，快且省心。
  • 图走 OSS：图片放阿里云 OSS，文章里引用链接，不塞进仓库。

两件容易被忽略但必须做的事

1. 放开 AI 爬虫。 我希望博客被 AI 搜索抓到、被引用。但 Cloudflare 对新域名默认会拦 AI 爬虫，所以要主动在 robots 里放行 GPTBot、OAI-SearchBot、ClaudeBot、PerplexityBot，并把 sitemap 提交给 Google 和 Bing。AI 时代，博客的意义正从”分发信息”转向”沉淀一份可被引用、带署名的第一手内容”——前提是得先让机器能读到。

2. 图片去 EXIF。 流水线里加一步 exiftool -all=，把照片的 GPS、设备、时间都清掉。这既是体积优化，更是隐私——不想自己拍的照片泄露家的位置。

一个要提醒自己的坑

搭这套流水线本身，是一件对我这种人极有诱惑力的”元层任务”：它边界清晰、有技术感、做完很有成就感，而且看起来和”写文章”是一回事——其实不是。真正的产出是文章，不是管道。所以给自己定了个护栏：先手动发几篇，再来优化流水线；不然很容易把精力全花在打磨一个还没几篇文章在用的系统上。

顺带：评论系统要迁移

旧的评论和访客统计依赖 LeanCloud，而 LeanCloud 已经官宣停服。这部分一年内会失效，得趁早导出数据、换到边缘 KV 方案。这算流水线维护的一部分，另开一篇再记。
