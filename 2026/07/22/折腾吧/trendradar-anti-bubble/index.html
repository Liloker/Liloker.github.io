给自己做一个反信息茧房的资讯+股票监测

发表于2026-07-22|更新于2026-07-22|折腾吧
|总字数:608|阅读时长:1分钟|浏览量:

我每天用 AI 爬一遍新闻和盯一些标的。久而久之发现，推荐算法喂给你的东西越来越像你昨天看的——这篇写我为了对抗这件事做的一个自用小工具。

起因：两种信息需求是反的

我把信息需求分成两类：

  • 定向搜索：我有明确问题，直接问 AI 更好。
  • 随机探索：我不知道自己该知道什么，需要被”撞见”新东西。

小红书、抖音这类推荐算法擅长第一类的伪装、却毁掉第二类——它不停给你更多同类，把探索收窄成回音。Twitter 信源质量高、干货多，但我没精力天天自己汇总。于是做了这个东西。

它做什么

一个自用的资讯聚合 + 股票监测流水线：

  • 爬取：抓多个信源的内容。
  • 摘要：用 LLM 把长内容压成要点，省得我一条条读。
  • 监测：盯一些标的的动态。
  • MCP 工具：把它做成了带 MCP 工具的形式，方便直接在对话里调用。

核心设计：一个”新词栏”

这是我最满意的一处。对抗信息茧房，光”多抓几个源”没用，因为还是会重复。我加了一个很笨但有效的机制：

今日出现的专有名词 − 过去 30 天出现过的专有名词 = 本周新词

也就是做一个集合差集，单独列一栏”你这段时间没见过的词”。重复的资讯自动沉下去，真正新增的概念浮上来。把”偶遇”这件事工程化了。

当然，线下的随机源（书店、漫展、陌生人）是技术替代不了的——新词栏只是补上线上这一半。

一点工程上的取舍

  • 省 token 的正确做法是换数据源，不是换模型。结构化 JSON 比渲染后的 DOM 省 20–50 倍 token。所以能拿结构化接口就不要去解析网页。
  • 流水线计划迁进 Docker 容器，方便长期稳定跑。

边界

这是个自用工具，没有做成产品，也没打算。它解决的是我自己的一个具体问题——怎么每天用最低的注意力成本，既不漏重要信息，又能撞见新东西。文中不涉及我的任何实际持仓。
